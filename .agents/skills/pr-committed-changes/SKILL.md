# 커밋된 변경사항으로 PR 생성

현재 브랜치에 이미 존재하는 커밋으로 GitHub PR을 생성한다. 커밋되지 않은 모든 워킹 트리 변경사항은 보존하고 PR에서 제외한다.

## 작업 절차

1. 저장소를 변경하지 않고 상태를 확인한다.
   - `git status -sb`, `git branch --show-current`, `git remote -v`를 실행한다.
   - 워킹 트리 변경사항을 스테이징, 커밋, stash, clean, reset하거나 다른 방식으로 변경하지 않는다.
   - 수정됨, 스테이징됨, 미추적 상태의 파일이 제외된다는 사실을 사용자에게 알린다.

2. 기준 브랜치를 결정한다.
   - 사용자가 명시한 기준 브랜치를 사용한다.
   - 지정되지 않았다면 `refs/remotes/<remote>/HEAD` 또는 `gh repo view --json defaultBranchRef`에서 원격 기본 브랜치를 확인한다.
   - 저장소 설정에서 다른 push 원격이 명확히 확인되지 않는 한 `origin`을 우선한다.
   - 네트워크를 사용할 수 있으면 비교 전에 선택한 원격 기준 브랜치를 fetch한다.

3. 커밋된 PR 범위를 계산한다.
   - 로컬 기준 브랜치가 아니라 원격 기준 ref와 `HEAD`를 비교한다.
   - `git rev-list --left-right --count <remote>/<base>...HEAD`를 실행해 behind/ahead 개수를 보고한다.
   - `git log --oneline <remote>/<base>..HEAD`를 실행해 현재 브랜치에만 존재하는 커밋을 나열한다.
   - `git diff --stat <remote>/<base>...HEAD`를 실행하고 커밋된 diff를 확인한다.
   - 현재 브랜치에만 존재하는 커밋이 없으면 중단한다.
   - 원격 기준 브랜치에서 이미 도달 가능한 커밋은 PR 변경사항으로 설명하지 않는다.

4. 안전하게 검증한다.
   - 항상 `git diff --check <remote>/<base>...HEAD`를 실행한다.
   - 관련 없는 워킹 트리 변경사항의 영향을 받지 않고 커밋된 `HEAD`만 검증할 수 있을 때에만 프로젝트 검사를 실행한다. 그렇지 않으면 생략하고 이유를 알린다.
   - 사용자가 별도로 요청하지 않는 한 관련 없는 오류를 수정하거나 PR에 포함하지 않는다.

5. 원격 작업 준비 상태를 확인한다.
   - 인증된 GitHub 연결 또는 `gh` 세션을 요구한다.
   - 사용자가 인증한 후 `gh auth status`가 샌드박스 안에서만 실패하면 인증이 잘못됐다고 판단하기 전에 허용된 키체인 접근으로 다시 시도한다.
   - 동일한 head와 base를 사용하는 열린 PR이 있는지 확인한다. 중복 PR을 만들지 말고 기존 PR을 반환한다.
   - 현재 브랜치의 커밋된 `HEAD`만 push한다. 워킹 트리 변경사항은 push에 포함하지 않는다.

6. 커밋된 diff를 바탕으로 PR을 작성한다.
   - 현재 브랜치에만 존재하는 모든 커밋과 실제 diff를 바탕으로 간결한 제목을 작성한다.
   - 변경 내용, 변경 이유, 영향, 검증 결과를 포함하는 Markdown 본문을 작성한다.
   - 도움이 된다면 정확한 커밋 수와 파일 수를 명시한다.
   - 사용자가 명시적으로 리뷰 준비 완료 상태를 요청하지 않는 한 Draft PR을 기본값으로 사용한다.

7. PR을 생성한다.
   - 연결된 GitHub 앱의 PR 생성 기능을 우선한다.
   - 커넥터로 생성할 수 없으면 `gh pr create`를 사용한다.
   - 선택한 기준 브랜치를 base로, 현재 브랜치를 head로 사용한다.

8. 결과를 보고한다.
   - 클릭 가능한 PR URL, PR 번호, base, head, 커밋 수, 검증 결과, 미커밋 변경사항이 제외됐다는 확인을 제공한다.
   - 사용자가 충돌 해결을 요청하지 않는 한 브랜치 기록을 변경하지 말고 merge conflict 또는 병합 불가 상태를 보고한다.

## 안전 규칙

- `<remote>/<base>..HEAD`에 포함된 커밋만 PR 범위로 취급한다.
- 이 작업 절차에서는 `git add -A`를 사용하거나 커밋을 생성하지 않는다.
- 로컬의 unstaged, staged, untracked 파일을 절대 포함하지 않는다.
- 사용자의 별도 명시적 요청 없이 force-push, rebase, 기준 브랜치 merge 또는 기록 재작성을 하지 않는다.
- 동일한 head/base 조합으로 중복 PR을 생성하지 않는다.
